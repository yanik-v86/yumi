# Задачи: общая система провайдеров нейронок (GTK + веб-панель)

Статус: **РЕАЛИЗОВАНО — P-01…P-09 DONE, проверки P-08 зелёные**.  
Дата: 2026-11-27.  
Передаточный документ: `docs/handoff-llm-providers.md` (контракты, потоки, риски).  
Обязательно к прочтению: `AGENTS.md`, `docs/handoff-web-panel.md`.  
Пересечение: `docs/tasks-agent-mcp.md` T-01/T-03 и `docs/handoff-agent-mcp.md` §3.1 — в части реестра провайдеров и ключей считаются **переопределёнными** этим планом; агентный цикл T-02 и дальше остаётся в силе и должен использовать общий реестр.

## Решения, зафиксированные в плане (подтвердить перед P-01)

1. Реестр и транспорт — новый чистый модуль `yumi/llm.py` (без GTK, без веб-панели). Два «диалекта»: `ollama` (native API) и `openai` (OpenAI-совместимый API). Новые провайдеры добавляются **настройкой**, без правки кода.
2. Список провайдеров хранится в `DEFAULT_SETTINGS['llm_providers']` как список записей `{id, name, kind, url, default_model, enabled}`; секреты — **в отдельном файле** `CONFIG_DIR/'llm_keys.json'` с правами `0600`, а не в `settings.json`.
3. Старый облачный провайдер переносится миграцией как обычная запись `kind: 'openai'` с id `cloud`; брендовых констант, ветвлений и строк в коде/UI/README не остаётся. Единственное допустимое упоминание старых ключей — таблица легаси-имен в `yumi/llm_migrate.py` (одноразовая миграция). Если владелец требует ноль упоминаний даже там — миграцию убрать и дать инструкцию «добавьте провайдер вручную», но это нарушит совместимость старых `settings.json` (не рекомендуется).
4. Локальный Ollama тоже становится записью реестра (id `local`). Эмбеддинги не должны зависеть от выбранного чат-провайдера: для них вводится отдельный ключ `embed_url`.
5. `chat_provider` остаётся строкой — теперь это **id записи**; `chat_model` остаётся глобальным, но при выборе провайдера сбрасывается на `default_model` этого провайдера (в GTK и в панели одинаково).
6. Распределение интерфейсов, зафиксированное владельцем: **GTK — только переключение провайдера и модели** (из уже созданных записей); **создание/правка/удаление/проверка/обновление моделей — только в админке** (веб-панель). Это явное исключение уже записано в `AGENTS.md`. Обе точки читают один реестр и одну функцию выбора; GTK не получает CRUD-кнопок и полей ключа.
7. `docs/tasks-agent-mcp.md` и `docs/handoff-agent-mcp.md` после P-07 указывают на этот реестр; у агента не должно быть второго «своего» списка провайдеров и дефолта с брендом.

## Фаза 1 — ядро реестра

### P-01. Реестр, адаптеры и хранилище ключей (P0)

**Статус:** DONE (99923a8).  
**Зависит от:** —  
**Файлы:** `yumi/llm.py` (новый), `yumi/llm_keys.py` (новый), `tests/test_llm.py` (новый).

**Что сделать:**
- Без GTK и `webpanel`: только stdlib (`urllib`, `json`, `re`, `time`).
- `KINDS` с двумя адаптерами:
  - `ollama`: `GET {url}/api/tags` (поле `models[].name`), `POST {url}/api/chat` (тело `model/messages/stream/options.num_predict`, `think`), поток — NDJSON (`message.content`, `done`).
  - `openai`: `GET {url}/models` (поле `data[].id`, заголовок `Authorization: Bearer`), `POST {url}/chat/completions` (`model/messages/stream/max_tokens`, Bearer), поток — SSE (`data:`, `[DONE]`, `choices[0].delta.content`).
- Валидация записи в одном месте (`llm.validate_record`): `id` — `[a-z0-9_-]{1,32}`, уникален; `name` ≤ 60; `kind` ∈ `KINDS`; `url` — только `http(s)://`, ≤ 400; `default_model` ≤ 200; `enabled` — bool; `models` — список строк ≤ 200; ключ **не** является полем записи.
- Публичный контракт: `providers(settings)`, `get(settings, id)`, `normalize_list(value)`, `resolve(settings, id) -> {url, key, kind, default_model}`, `models(settings, id, timeout=4)`, `test(settings, id, timeout=4)`, `ask(...)` / `ask_stream(...)` (аргумент `tools=None` оставить заготовкой под агент).
- `models()` и `test()` никогда не бросают наружу исключение; ошибки обобщены (`'no api key'`, `'the provider did not answer'`, `'the provider has no models'`) — без URL и ключа.
- `llm_keys.py`: `CONFIG_DIR/'llm_keys.json'`, `mkdir(parents=True, exist_ok=True)`, файл `0600`, запись через `.tmp` + `os.replace()`, функции `load()/get(id)/set(id, value)/delete(id)`. Пустой ключ = удаление записи. Логи и исключения не содержат значение ключа.
- Никаких брендовых имен/констант/URL в этом модуле: «облачный» провайдер — просто пользовательская запись с `kind: 'openai'`.

**Критерии приёмки:**
- Поддельный HTTP-сервер проверяет оба диалекта: `/api/tags` + `/api/chat` (NDJSON) и `/models` + `/chat/completions` (SSE).
- Невалидная запись (плохой id, `ftp://`, дубликат, лишний ключ внутри записи) отклоняется.
- Файл ключей создаётся с режимом `0600`; ключ не попадает в логи, repr'ы и ответы API.
- Пустой ключ у `openai`-провайдера даёт мгновенный отказ без запроса в сеть.

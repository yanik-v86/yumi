## 1. Задача (кратко)

Две связанные проблемы в озвучке:

1. **Английские слова звучат плохо.** В смешанном RU/EN тексте латинские run'ы
   уходят в английский Silero-спикер (`tts_en_speaker`), и это режет слух в
   русской речи Юми. Нужен opt-in режим: перед озвучкой английские буквы/слова
   транслитерируются в русские звуки, чтобы их читал русский TTS.
   Примеры: `Ollama` → `Оламма` (или близкий фонетический вариант),
   `Good morning` → `Гуд морнинг`.
2. **Знак `%` не озвучивается.** `71%` после текущей нормализации превращается
   в `семьдесят один%` — символ остаётся и Silero обычно его игнорирует/читает
   плохо. Нужно произносить «процент/процента/процентов» или `percent`.

Требование пользователя по UI: тумблер в `/#/voice`, карточка
`3. Голос: чем она говорит`, **под полем «Английский голос»**
(`tts_en_speaker`).

По `AGENTS.md`: любая новая настройка/поведение должна появиться и в Юми
(GTK), и в веб-панели. Исключений здесь нет.

| Нормализация/TTS | `yumi/tts.py:322-356` | `normalize -> truncate(500) -> _convert_digits_for_tts -> apply_stress -> cache key -> _lang_runs -> daemon /tts?lang=...` |

### Почему английский звучит плохо

`tts.py:_lang_runs()` (`264-283`) делит текст по Unicode-скрипту: кириллица → `ru`,
латиница → `en`, числа/символы прилипают к соседям. Каждый run отправляется
демону с `lang=ru|en`, а демон выбирает `ru_speaker`/`en_speaker`.
Итог: английские слова в русской фразе читаются английским Silero-голосом.

### Почему `%` пропадает

`_convert_digits_for_tts()` (`442-466`) сначала заменяет время `HH:MM`, потом
делает `re.sub(r'\d+', num_repl, text)`. Для `71%` цифры становятся словами, а
`%` остаётся символом: `семьдесят один%`. В `yumi/facts.py:102-111` уже есть
факты с процентами.

- Дефолты: `yumi/config.py:30-35` (`voice_vol`, `voice_kind`, `tts_ru_speaker`,
  `tts_en_speaker`, `tts_ru_model`, `tts_pitch`).
- TTS-профиль демона: `config.TTS_PROFILE_KEYS/DEFAULTS` (`config.py:224-232`),
  `tts.py:128-205`.
- Каталог панели: `yumi/webpanel/catalog.py:110-114,160-165,192-197,229,236-238,259,270,288-293,418-425`.

## 3. Предлагаемый дизайн

### 3.1. Настройка-тумблер

Рекомендуемое имя: `voice_en_ru` (bool, default `false`).

Почему **не** `tts_*`:
- `ui/webpanel.py:531-535` делает `tts.sync_profile()` на любой ключ, начинающийся
  с `tts_`. Транслит — клиентская предобработка текста, не профиль демона;
  рестарт демона не нужен.
- `TTS_PROFILE_KEYS` в `config.py` — только параметры `tts.json`. Туда ключ
  добавлять нельзя.

Смысл: когда `voice_en_ru == true`, латинские слова перед TTS преобразуются в
кириллическую фонетическую форму и озвучиваются русским голосом. Режим opt-in,
по умолчанию выключен.

Альтернативные имена, если захочется другое: `voice_translit_en`, `voice_en_as_ru`.
Главное — не `tts_` префикс без изменения условий синка.

### 3.2. Где делать транслит

Лучший choke point — `tts.speak()` в `yumi/tts.py`, потому что его вызывают:
- `ui/senses.py:113,148` (обычный и стриминг);
- `ui/bridge.py:532` (`voice_test`).

Предлагаемая сигнатура:

```py
def speak(text, volume=0.5, en_ru=False):
    ...
```

Вызывающие стороны передают `bool(settings.get('voice_en_ru'))`. Это явно,
легко тестируется и не требует глобального состояния. Альтернатива — модульный
флаг в `tts.py`, но явный параметр прозрачнее.

Важно: транслитировать нужно **только текст, уходящий в TTS**. Пузырь
(`brain.bubble['text']`) должен оставаться оригинальным.

### 3.3. Порядок нормализации

Текущий порядок (`tts.py:327-331`):

```py
text = ' '.join(str(text).split())[:500]
text = _convert_digits_for_tts(text)
text = apply_stress(text)
```

Предлагаемый порядок:

```py
text = ' '.join(str(text).split())[:500]
if en_ru:
    text = translit_en_to_ru(text)      # латиница -> кириллица (фонетика)
text = _convert_digits_for_tts(text)     # % + время + числа в слова
text = apply_stress(text)
```

Почему транслит **до** чисел/процентов: чисто английская фраза
`Good morning at 14:05` после транслита получит кириллицу, `_is_ru()` станет
True, и время/числа будут озвучены русскими словами, а не английскими словами,
которые потом транслитерируются криво.

### 3.4. Нормализация `%`

Делать всегда, независимо от `voice_en_ru`.

Предлагаемый подход: до общего `re.sub(r'\d+', num_repl, text)` заменить
`(\d+)\s*%` на число словами + слово «процент/percent» с учётом языка и
склонения.

```py
_PERCENT_RE = re.compile(r'(\d+)\s*%')

def _percent_word(n, ru):
    if ru:
        return _ru_words(n) + ' ' + _ru_plural(n, 'процент', 'процента', 'процентов')
    return _en_number(n) + ' percent'
```

В `_convert_digits_for_tts()`:

```py
text = _TIME_RE.sub(time_repl, text)
text = _PERCENT_RE.sub(lambda m: _percent_word(int(m.group(1)), ru), text)
return re.sub(r'\d+', num_repl, text)
```

Так число не теряется до склонения: `71%` → `семьдесят один процент`,
`2%` → `два процента`, `25%` → `двадцать пять процентов`.

### 3.5. Транслитератор

Нужен прагматичный rule-based mapper, не идеальный фонетический движок.
Разместить в `yumi/tts.py` рядом с нормализацией (или маленьким helper в том же
модуле, если функция разрастётся).

Минимальные требования:
- не трогать кириллицу, цифры, пунктуацию, пробелы;
- обрабатывать диграфы раньше одиночных букв (`sh`, `ch`, `th`, `ph`, `ck`,
  `qu`, `oo`, `ee`, `ea`, `ou`, `ow`, `igh`, `ing`, `tion/sion`, ...);
- работать регистронезависимо по логике, но исходный текст в TTS можно
  безопасно приводить к обычной форме — TTS всё равно читает слова;
- оставить таблицу/словарь легко расширяемой (для исключений).

Пример ожидаемого поведения:

| Вход | Ожидаемо (примерно) |
|------|---------------------|
| `Ollama` | `Оллама` / `Олама` — близко по звуку |
| `Good morning` | `Гуд морнинг` |
| `OpenCode` | `Опенкод` / `Опэнкод` — зависит от правил |
| `Привет, Ollama!` | `Привет, Оллама!` |

Точное написание для спорных слов зафиксировать тестами и при необходимости
дать маленький словарь переопределений.

## 6. Подводные камни и тонкости

### Транслит

- **Приблизительность.** Английское чтение нерегулярно (`though`, `knight`,
  `colonel`, `read`, `live`). Rule-based транслит будет «достаточно хорошо»,
  но не идеально. Нужны тесты на целевые примеры и лёгкий путь добавить
  исключения.
- **Диграфы и контекст.** `th` может звучать как `з/с/д`; `c` как `к/с`; `g`
  как `г/дж`; `oo/ea/ou` зависят от слова. Для MVP — разумные дефолты + тесты.
- **Аббревиатуры ALL-CAPS.** `API` буквами даст `АПИ`, `USB` → `УСБ`,
  `HTTP` → `ХТТП`. Это не всегда то, что ожидает пользователь («эй-пи-ай»).
  Нужна явная стратегия: либо оставить как есть, либо детектить 2–5 заглавных
  латинских букв и озвучивать буквенными именами.
- **CamelCase/бренды.** `iPhone`, `OpenCode`, `GitHub`, `YouTube`, `macOS`.
  Простая побуквенная логика может дать странный результат. Словарь исключений
  сильно поможет.
- **URL/пути/код/флаги.** `https://github.com`, `/usr/bin/python3`,
  `git commit --amend`, `snake_case` — транслит сделает их нечитаемыми. Режим
  opt-in снижает риск, но стоит рассмотреть детект URL/путей или явно описать
  ограничение в хинте.
- **Границы стриминг-чанков.** `speak_stream()` синтезирует куски отдельно.
  Диграф на границе чанка (`mor` + `ning`) может транслитерироваться неверно.
  Риск небольшой, но реальный; если всплывёт — транслитерировать до разбиения
  на TTS-чанки или хранить хвост.
- **Уже транслитерированная латиница.** «privet», «spasibo» в латинице станут
  двойной транслитерацией. Это редкий кейс, но возможен.

### Проценты

- **Склонение RU.** Нужен `_ru_plural`: 1 процент, 2 процента, 5 процентов,
  21 процент, 11 процентов. Поэтому `%` обрабатывается до замены числа словами.
- **Пробел перед `%`.** Поддержать `100 %`.
- **Десятичные проценты.** `3.5%` / `3,5%` сейчас не покрыты обычным `\d+`
  сценарием; решить: поддержать сейчас или явно оставить как ограничение.
- **Язык.** `_is_ru()` определяет язык по наличию кириллицы. Для строк без
  кириллицы использовать `percent`. Это согласуется с текущей логикой чисел.

### Интеграция

- **Не трогать `tts.json` профиль.** Ключ не входит в `TTS_PROFILE_KEYS`.
- **Не использовать `tts_` префикс** без правки `ui/webpanel.py:531-535`, иначе
  будет лишний рестарт демона при каждом переключении.
- **`brain.py:1267`** делает `say_sample()` для `arg.startswith('tts_')` при
  активном TTS. Новый ключ не `tts_`, поэтому sample не вызовется автоматически.
  Это ок; при желании можно добавить отдельное поведение.
- **Кэш.** `tts.speak()` кэширует по `profile|volume|text` (`tts.py:336`).
  Транслитированный итоговый текст должен участвовать в ключе. Не менять ключ
  после вычисления хэша.
- **Пузырь не менять.** Пользователь видит оригинальный текст; транслит — только
  для аудио. Не путать с `spoken=` в `say_text`, который уже поддерживает
  отдельный текст для голоса.
- **`voice_test`** вызывает `tts.speak` напрямую и должен получить флаг.
  `voice_speak` идёт через `brain.say_text` — покроется обычным путём.
- **EN-спикер становится неактуальным в режиме транслита.** Хинт в UI должен
  быть честным: латиница уходит в русскую озвучку.

### Паритет и процесс

- **AGENTS.md:** настройка должна быть и в GTK, и в веб-панели. GTK звук
  редактируется в `brain.py:set_sound` — тумблер должен быть рядом с
  `tts_en_speaker`.
- **Схема webpanel.** `tests/test_webpanel.py` проверяет, что ключи из
  `DEFAULT_SETTINGS` попадают в схему; после добавления ключа тест должен
  остаться зелёным.
- **Документация.** После реализации обновить `README.ru.md`, `README.md` и
  при необходимости `docs/handoff-voice-controls.md`.

## 7. Проверки

Базовые проверки перед/после изменений:

```bash
# точечные тесты
python3 tests/test_tts.py
python3 tests/test_webpanel.py

# если добавлен новый тест нормализации
python3 tests/test_tts_norm.py

# компиляция затронутых Python
python3 -m py_compile \
  yumi/config.py yumi/tts.py yumi/brain.py \
  yumi/ui/senses.py yumi/ui/bridge.py yumi/ui/webpanel.py yumi/ui/app.py \
  yumi/webpanel/catalog.py

# проверка JS страниц/фронта
for f in yumi/webui/static/js/pages/voice.js \
         yumi/webui/static/js/ui.js \
         yumi/webui/static/js/api.js; do
  node --input-type=module --check < "$f" || echo "FAIL $f"
done
```

Полный `pytest tests/ -q` в этом репозитории может быть неудобен из-за старых
standalone-тестов; сверяться с текущей практикой проекта и `AGENTS.md`.

Живая приёмка:

1. Открыть `/#/voice` → `3. Голос: чем она говорит`.
2. Убедиться, что тумблер есть под «Английский голос».
3. Включить тумблер, нажать «Послушать голос»/сказать фразу: `Ollama`,
   `Good morning`, `Привет, OpenCode!`, `Загрузка 71%`.
4. Выключить тумблер — убедиться, что старое поведение вернулось.
5. Проверить GTK: Настройки → Звук → тумблер на месте, сохраняется.
6. Проверить, что пузырь показывает оригинальный текст, а звучание — изменённое.

## 8. Открытые вопросы для реализации

- **Имя настройки**: `voice_en_ru` ок? Если хочется более явное — согласовать,
  но сохранить не-`tts_` префикс.
- **Стратегия аббревиатур**: буквами (`АПИ`) или по именам букв (`эй-пи-ай`)?
  Нужен продуктовый выбор; можно начать с простого и зафиксировать тестами.
- **Словарь исключений**: где хранить — в коде, в `~/.config/yumi/*.json`, или
  переиспользовать существующий `stress.json`/отдельный файл? Для MVP хватит
  встроенной таблицы + тестов.
- **Десятичные проценты**: поддерживать ли `3.5%`/`3,5%` в первом проходе.
- **URL/код в транслите**: игнорировать паттерны или оставить как есть в
  opt-in режиме.
- **Нужен ли sample при переключении в GTK**: не обязательно; можно решить по
  UX в ходе реализации.
